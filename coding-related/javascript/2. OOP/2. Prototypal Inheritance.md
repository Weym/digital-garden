# JavaScript Prototypes & Inheritance: Cheat Sheet

## 1. Prototypal Inheritance

In JavaScript, inheritance is based on objects rather than classes. A **Prototype** is simply a parent object that provides shared properties and methods to its children.

```js
const x = {}
const y = {}

// Both share the same "Object Base" (the root prototype)
Object.getPrototypeOf(x) === Object.getPrototypeOf(y) // true
```

---

## 2. The Prototype Chain

When you access a property, JS engine searches:

1.  The **Instance** itself.
2.  The **Prototype** of the instance.
3.  The **Grandparent Prototype**, continuing until it hits the root object (`Object.prototype`) or `null`.

---

## 3. Custom Prototypal Inheritance

To make one constructor inherit from another (e.g., `Circle` inheriting from `Shape`), you must manually link their prototypes and reset the constructor reference.

```js
function Shape(color) {
  this.color = color
}
Shape.prototype.duplicate = function () {
  console.log("duplicate")
}

function Circle(radius, color) {
  // 1. Call the Super Constructor to inherit instance properties
  Shape.call(this, color)
  this.radius = radius
}

// 2. Link Prototypes: Circle.prototype now inherits from Shape.prototype
Circle.prototype = Object.create(Shape.prototype)

// 3. Reset Constructor: Object.create wipes out the constructor, so we fix it
Circle.prototype.constructor = Circle

Circle.prototype.draw = function () {
  console.log("draw")
}
```

---

## 4. Property Descriptors

Every property has attributes (descriptors) that control how it behaves.

```js
let person = { name: "John" }

// Get descriptors (writable, enumerable, configurable)
let descriptor = Object.getOwnPropertyDescriptor(person, "name")

// Set descriptors
Object.defineProperty(person, "name", {
  writable: false, // Value cannot be changed
  enumerable: false, // Won't show up in Object.keys() or for...in
  configurable: false, // Cannot be deleted or re-configured
})
```

---

## 5. Constructor Prototypes

Functions in JavaScript have a `prototype` property. This is **not** the prototype of the function itself, but the object that will be used as the **parent** for any objects created using that function as a constructor.

```js
function Circle(radius) {
  this.radius = radius
}

// Parent of all circles
Circle.prototype

const circle = new Circle(1)
Object.getPrototypeOf(circle) === Circle.prototype // true
```

---

## 6. Prototype vs. Instance Members

To optimize memory, move methods that are common to all instances into the prototype.

| Member Type          | Defined In                                 | Storage                              |
| :------------------- | :----------------------------------------- | :----------------------------------- |
| **Instance Member**  | Inside Constructor (`this.draw`)           | Replicated in every object instance. |
| **Prototype Member** | On the Prototype (`Circle.prototype.draw`) | Stored once in the parent object.    |

---

## 7. Iterating Members

Be aware of where a property lives when iterating through an object.

```js
// Object.keys returns ONLY instance members
console.log(Object.keys(c1)) // ["radius"]

// for...in returns ALL members (instance + prototype)
for (let key in c1) console.log(key) // "radius", "draw"

// Check specifically for instance ownership
c1.hasOwnProperty("radius") // true
```

---

## 8. Advanced Knowledge & Tips

- **Calling the Super Constructor:** Use `BaseFunction.call(this, args)` inside the child constructor. Without this, the child won't inherit properties defined with `this` in the parent.
- **Method Overriding:** You can redefine a parent method in the child prototype. JS will find the child's version first in the prototype chain.
- **Intermediate Function Inheritance:** For cleaner code, you can wrap the inheritance logic in a reusable function:
  ```js
  function extend(Child, Parent) {
    Child.prototype = Object.create(Parent.prototype)
    Child.prototype.constructor = Child
  }
  ```
- **Composition over Inheritance:** Avoid deep inheritance hierarchies (more than 1-2 levels). If you find yourself creating complex trees, consider using **Mixins** to compose objects from smaller features.
- **The "Live" Prototype:** If you add a method to `Shape.prototype` even after creating a `Circle` instance, that circle will have access to the new method immediately.
