# JavaScript Modules & Tooling: Cheat Sheet

## 1. Why Modules?

Modules allow us to split code into multiple files, providing:

- **Maintainability:** Easier to fix and update smaller files.
- **Reuse:** Use the same code across different parts of an application.
- **Abstraction:** Hide complex implementation details and only expose what is necessary.

| System          | Environment                   | Syntax                                 |
| :-------------- | :---------------------------- | :------------------------------------- |
| **CommonJS**    | Node.js (Standard)            | `require()` / `module.exports`         |
| **ES6 Modules** | Modern Browsers / Modern Node | `import` / `export`                    |
| **AMD / UMD**   | Legacy Browser Apps           | Specialized syntax (rarely used today) |

---

## 2. CommonJS (Node.js)

In CommonJS, every file is a module. Variables defined in a file are private to that file.

```js
// circle.js
class Circle {
  constructor(radius) {
    this.radius = radius
  }
  draw() {
    console.log("draw")
  }
}
module.exports = Circle // Exporting the class

// index.js
const Circle = require("./circle") // Importing the class
const c = new Circle(10)
```

---

## 3. ES6 Modules (Native JS)

The modern standard for JavaScript modules. By default, everything is private unless `export` is used.

```js
// circle.js
export class Circle {
  constructor(radius) {
    this.radius = radius
  }
  draw() {
    console.log("draw")
  }
}

// index.js
import { Circle } from "./circle.js"
const c = new Circle(10)
```

> **Note:** To run ES6 modules directly in a browser without a bundler, you must use `<script type="module" src="index.js"></script>`.

---

## 4. ES6 Tooling: Transpilers & Bundlers

Because older browsers don't support modern ES6+ features, we use a "Toolchain."

- **Transpiler (Babel):** Converts modern JS (ES6+) into ES5 code that all browsers understand.
- **Bundler (Webpack):** Combines multiple JS files into a single bundle, minifies (uglifies) code to reduce file size, and manages assets like CSS/Images.

---

## 5. Babel Setup

Babel requires Node.js and NPM.

```sh

# Initialize project and install Babel tools

npm init --yes
npm i babel-cli babel-core babel-preset-env --save-dev
```

```json
// package.json configuration
"scripts": {
"babel": "babel --presets env index.js -o build/index.js"
}
```

---

## 6. Webpack Setup

Webpack automates the entire process of transpiling and bundling.

```sh

# Typical installation of necessary loaders and webpack

npm i webpack webpack-cli babel-loader --save-dev
```

```json
// package.json for daily development
"scripts": {
"build": "webpack -w"
}
```

_The `-w` flag "watches" your files and re-bundles automatically whenever you save a change._

---

## 7. Advanced Knowledge & Tips

- **Circular Dependencies:** Avoid "A imports B, and B imports A." This can lead to `undefined` values or crashes because one module might be accessed before it finishes initializing.
- **Named vs. Default Exports:** Prefer **Named Exports** (`export const X`) for utility libraries. It makes it easier for bundlers to perform **Tree Shaking** (removing unused code) and provides better IntelliSense in editors.
- **Dynamic Imports:** You can load modules on demand using `import('./module.js').then(...)`. This is the basis for **Code Splitting**, which reduces the initial load time of your website.
- **Babel Polyfills:** Transpiling syntax (like `class` to `function`) isn't enough for new objects like `Promise` or `Map`. You often need a **Polyfill** (like `core-js`) to provide those features to old browsers.
- **Browser Compatibility (browserslist):** You can define exactly which browsers you want to support in your `package.json` using a `browserslist` key. Babel and Autoprefixer will use this to generate the minimum amount of code necessary.
- **Hot Module Replacement (HMR):** When using a dev server, HMR allows you to update specific modules in the browser without a full page refresh, preserving the state of your application.
