# JavaScript Objects & Abstraction: Cheat Sheet

## 1. Object Creation Patterns

There are three main ways to create objects. Choice depends on your preference for literal, functional, or class-like syntax.

| Pattern              | Example                                | Characteristics                          |
| :------------------- | :------------------------------------- | :--------------------------------------- |
| **Object Literal**   | `const obj = { ... }`                  | Best for simple, one-off objects.        |
| **Factory Function** | `function create() { return { ... } }` | Returns a new object; uses `camelCase`.  |
| **Constructor**      | `function Circle() { this.x = 1; }`    | Uses `PascalCase` and the `new` keyword. |

```js
// Constructor Example
function Circle(radius) {
  this.radius = radius
  this.draw = function () {
    console.log("draw")
  }
}
const circle = new Circle(1) // 'new' creates an empty {} and sets 'this'
```

---

## 2. Functions are Objects

In JavaScript, functions are objects. They have properties like `name`, `length` (number of parameters), and a `constructor`.

```js
console.log(Circle.name) // "Circle"
// Internally, JS uses the Function() constructor to build them
```

---

## 3. Value vs. Reference Types

Understanding memory allocation is key to avoiding bugs when copying data.

- **Primitives (Value Types):** `Number`, `String`, `Boolean`, `Symbol`, `undefined`, `null`. Data is stored in the variable itself.
- **Reference Types:** `Object`, `Function`, `Array`. The variable stores a **reference** (address) to the location in memory.

```js
// Primitives: Copied by Value
let x = 10
let y = x // y is a separate copy of 10

// Objects: Copied by Reference
let a = { value: 10 }
let b = a // b points to the SAME object as a
a.value = 20 // b.value is now also 20
```

---

## 4. Working with Properties

You can dynamically add or remove properties after an object is created.

```js
const circle = new Circle(1)

circle.location = { x: 1 } // Dot notation
circle["location"] = { x: 1 } // Bracket notation (good for dynamic keys)

delete circle.location // Remove property
```

---

## 5. Enumerating & Iterating

Objects are not "iterable" (you can't use `for...of` directly), but you can extract their keys or entries.

```js
for (let key in circle) {
  console.log(key, circle[key])
}

const keys = Object.keys(circle) // Returns array of keys
const entries = Object.entries(circle) // Returns array of [key, value] pairs

if ("radius" in circle) console.log("Yes") // Check for existence
```

---

## 6. Abstraction & Private Members

**Abstraction** means hiding complexity and showing only essentials. We use **local variables** (instead of `this`) inside constructors to create "private" members.

```js
function Circle(radius) {
  this.radius = radius // Public

  let defaultLocation = { x: 0, y: 0 } // Private (Local variable)
  let computeLocation = function () {} // Private method

  this.draw = function () {
    computeLocation() // Accessible via Closure
    console.log("draw")
  }
}
```

---

## 7. Getters and Setters

Use `Object.defineProperty` to allow external access to private variables without allowing direct modification or to add validation logic.

```js
function Circle(radius) {
  let defaultLocation = { x: 0, y: 0 }

  Object.defineProperty(this, "defaultLocation", {
    get: function () {
      return defaultLocation
    }, // Read access
    set: function (value) {
      // Write access + Validation
      if (!value.x || !value.y) throw new Error("Invalid.")
      defaultLocation = value
    },
  })
}
```

---

## 8. Advanced Knowledge & Tips

- **Shallow vs. Deep Cloning:** Using `const copy = { ...original };` only performs a **shallow copy**. If the object has nested objects, they are still linked by reference. For a true deep copy, use `structuredClone(original)`.
- **Immutability (Freeze vs. Seal):** \* `Object.freeze(obj)` prevents any changes (no new properties, no deletes, no value updates).
  - `Object.seal(obj)` prevents adding/deleting properties but allows updating existing values.
- **Property Shorthand:** If the key name and variable name are the same, you can omit the value: `const circle = { radius };` instead of `{ radius: radius };`.
- **Serialization:** Use `JSON.stringify(obj)` to convert an object to a string for APIs, and `JSON.parse(str)` to bring it back. Note that methods (functions) are lost during this process.
- **Closure Persistence:** Remember that private variables inside a constructor stay in memory as long as the object instance exists because the methods maintain a **closure** over them.
- **The `in` Operator vs `hasOwnProperty`:** `'radius' in circle` checks the object **and** its prototype chain. `circle.hasOwnProperty('radius')` only checks the instance itself.
