# JavaScript ES6 Classes: Cheat Sheet

## 1. ES6 Classes Overview

Classes are "syntactic sugar" over prototypal inheritance. They provide a cleaner, more organized way to create objects and handle inheritance.

```js
class Circle {
  constructor(radius) {
    this.radius = radius
    // Instance member (unique to each object)
    this.move = function () {}
  }

  // Prototype member (shared across all instances)
  draw() {}
}

const c = new Circle(1)
console.log(typeof Circle) // "function"
```

---

## 2. Hoisting & Definitions

Unlike function declarations, **Classes are not hoisted**. You must define a class before you can instantiate it.

| Type                  | Syntax                    | Hoisted? |
| :-------------------- | :------------------------ | :------- |
| **Class Declaration** | `class Circle {}`         | No       |
| **Class Expression**  | `const Circle = class {}` | No       |

---

## 3. Instance vs. Static Methods

- **Instance Methods:** Available on the object instance (e.g., `circle.draw()`).
- **Static Methods:** Available on the Class itself. Used for utility functions not tied to a specific object's state (like `Math.floor`).

```js
class Circle {
  constructor(radius) {
    this.radius = radius
  }

  draw() {} // Instance Method

  static parse(str) {
    // Static Method
    const radius = JSON.parse(str).radius
    return new Circle(radius)
  }
}

const c = Circle.parse('{ "radius": 5 }')
```

---

## 4. The "this" Keyword & Strict Mode

By default, the body of a class is executed in **Strict Mode**. This prevents `this` from pointing to the global `window` object if a method is called as a standalone function.

```js
class Circle {
  draw() {
    console.log(this)
  }
}

const c = new Circle()
const draw = c.draw
draw() // undefined (due to strict mode)
```

---

## 5. Private Members (Abstraction)

Hiding details and complexity through private properties.

### Approach: WeakMaps

WeakMaps provide true privacy because the keys (the object instance) are not accessible from the outside.

```js
const \_radius = new WeakMap();
const \_move = new WeakMap();

class Circle {
constructor(radius) {
\_radius.set(this, radius);

        // Use Arrow Function to inherit 'this' from constructor
        _move.set(this, () => {
            console.log('move', this);
        });
    }

    draw() {
        console.log(_radius.get(this));
    }

}
```

---

## 6. Getters and Setters

Use `get` and `set` keywords to treat methods like properties while adding validation logic.

```js
class Circle {
constructor(radius) { \_radius.set(this, radius); }

    get radius() { return _radius.get(this); }

    set radius(value) {
        if (value <= 0) throw new Error('Invalid radius');
        _radius.set(this, value);
    }

}
```

---

## 7. Inheritance & Method Overriding

Use `extends` to inherit and `super` to call the parent (base) constructor.

```js
class Shape {
  constructor(color) {
    this.color = color
  }
  move() {
    console.log("move")
  }
}

class Circle extends Shape {
  constructor(color, radius) {
    super(color) // Must call super before 'this'
    this.radius = radius
  }

  // Method Overriding
  move() {
    super.move() // Optional: call parent move
    console.log("circle move")
  }
}
```

---

## 8. Advanced Knowledge & Tips

- **Private Class Fields (#):** Modern JavaScript now supports a native syntax for private members. Using `#radius` instead of WeakMaps or Symbols provides built-in privacy that the engine optimizes.
- **The `new.target` Property:** Inside a constructor, `new.target` allows you to detect whether a function or constructor was called using the `new` operator. In inheritance, it refers to the class that was actually instantiated.
- **Static Initialization Blocks:** You can use `static { ... }` blocks within a class to perform complex initialization of static properties, including logic that requires access to private fields.
- **Mixins with Classes:** Since JavaScript doesn't support multiple inheritance, you can use a "Mixin" pattern: a function that takes a base class and returns a new class extending it with specific behaviors.
- **Performance of Classes:** While classes are "sugar," modern JS engines (V8) optimize class-based code better than manually linked prototypes because the structure is more predictable (Hidden Classes optimization).
- **Bound Methods:** To avoid `this` becoming undefined when passing methods as callbacks (like in React or Event Listeners), you can define methods as arrow functions directly in the class body: `handleClick = () => { ... }`.
