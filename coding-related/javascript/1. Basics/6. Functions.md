# JavaScript Functions: Cheat Sheet

## 1. Function Declarations vs. Expressions

There are two primary ways to define functions. The main difference is that Declarations are hoisted.

```js
// Function Declaration (Hoisted)
function walk() {
  console.log("walk")
}

// Anonymous Function Expression (Not Hoisted)
const run = function () {
  console.log("run")
}
```

---

## 2. Hoisting

JavaScript moves function declarations to the top of the current scope before code execution.

```js
walk() // Works!

function walk() {
  console.log("walk")
}

run() // Error: ReferenceError
const run = function () {
  console.log("run")
}
```

---

## 3. Arguments & The Rest Operator

Handling variable numbers of inputs.

- **arguments**: An array-like object available in all regular functions (contains all passed values).
- **Rest Operator (`...`)**: Modern way to collect arguments into a real array. Must be the last parameter.

```js
// arguments (Old way)
function sum() {
return Array.from(arguments).reduce((a, b) => a + b);
}

// Rest Operator (Modern)
function shoppingCart(discount, ...prices) {
const total = prices.reduce((a, b) => a + b);
return total \* (1 - discount);
}
```

---

## 4. Default Parameters

Assigning values to parameters if they are missing or `undefined`.

```js
// Tip: Put parameters with default values at the end
function calculateInterest(principal, rate = 3.5, years = 5) {
return principal _ (rate / 100) _ years;
}
```

---

## 5. Getters & Setters

Methods that behave like properties for better encapsulation.

```js
const person = {
  firstName: "John",
  lastName: "Smith",
  get fullName() {
    return `${this.firstName} ${this.lastName}`
  },
  set fullName(value) {
    const parts = value.split(" ")
    this.firstName = parts[0]
    this.lastName = parts[1]
  },
}

person.fullName = "Jane Doe" // Calls setter
```

---

## 6. Error Handling (Try/Catch)

Using "defensive programming" to handle invalid inputs or runtime errors.

```js
try {
  if (typeof value !== "string") throw new Error("Input must be a string")
} catch (e) {
  console.error(e.message) // Handles the thrown exception
}
```

---

## 7. Closures & Lexical Environment

A closure is the combination of a function and the lexical environment within which that function was declared.

```js
function multiplier(factor) {
// This inner function "remembers" the 'factor' variable
return function(number) {
return number \* factor;
};
}

const double = multiplier(2);
console.log(double(5)); // 10
```

---

## 8. The "this" Keyword & Binding

`this` is determined by how a function is called.

```js
const video = {
  title: "a",
  tags: ["a", "b"],
  showTags() {
    // Arrow functions inherit 'this' from showTags()
    this.tags.forEach(tag => console.log(this.title, tag))
  },
}

// Explicit Binding
function play() {
  console.log(this.name)
}
const user = { name: "John" }
play.call(user) // John
```

| Context                 | `this` refers to...                              | Example          |
| :---------------------- | :----------------------------------------------- | :--------------- |
| **Method**              | The object owning the method                     | `obj.play()`     |
| **Regular Function**    | Global Object (`window` / `undefined` in strict) | `play()`         |
| **Constructor**         | The new empty object created                     | `new Video()`    |
| **Arrow Function**      | Inherited from the surrounding scope (Lexical)   | `() => {}`       |
| **Manual (Call/Apply)** | The object passed as the first argument          | `play.call(obj)` |
| **Manual (Bind)**       | The object permanently tied to the function      | `play.bind(obj)` |

---

## 9. Development Tips

- **The "Call Stack" Awareness:** Be careful with deep recursion; every function call is added to the stack. Too many calls without a base case results in a "Stack Overflow."
- **Avoid "var" Pollution:** `var` attaches to the `window` object in browsers, which can conflict with 3rd-party libraries. Use `let/const`.
- **Arrow Functions for Lexical This:** When using callbacks inside objects (like `setTimeout` or `forEach`), arrow functions are the safest way to ensure `this` points to the object.
- **Factory Functions vs. Constructors:** Use **Factory Functions** (returning an object) if you want to avoid the complexities of `this` and `new`.
- **IIFE (Immediately Invoked Function Expressions):** Use these to create a private scope that executes immediately, preventing global scope pollution:
  ```js
  ;(function () {
    const privateVar = "top secret"
  })()
  ```
- **Function Composition:** Aim for small, single-responsibility functions that can be composed together for better testability and reuse.
